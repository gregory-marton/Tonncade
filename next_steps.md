- **#28 Device-rotation as a viewing angle, not just a resize**: in Gravity mode, rotating the device correctly keeps "higher pitch = up" fixed on screen, since falling pieces need a stable notion of "down" — that stays as is. In Blast, Snake, Melody, and Sandbox, none of which have gravity-driven mechanics, device rotation could instead let the Tonnetz visually rotate along with the phone (0°/90°/180°/270°), so physically turning the device reveals a different rotated view of the same fixed lattice, while controls/stats and — critically — each hex's in-grid note-name label counter-rotate individually to stay upright and legible regardless of the overall grid's rotation. - **#50 Sandbox (and perhaps Melody) should reach the full range of human hearing, not just a piano's range**: today Sandbox's board (`Board.radius = 5`) covers MIDI 25–95 (34.6Hz–1975.5Hz, ~5.8 octaves) — comfortably inside standard 88-key piano range (MIDI 21–108, 27.5Hz–4186Hz), so the board itself is the current bottleneck, not audio playback. But `Synth.playNote()` (`js/synth.js:72-76`) silently octave-wraps any non-harmonic note outside MIDI 21–108 back inside that range — a leftover from when the piano range was a reasonable assumption. If the board is later widened to actually reach toward the ~20Hz–20kHz range of human hearing (roughly MIDI 15–135), that clamp would quietly defeat the whole point by wrapping the extreme notes back into piano range before they ever reach the speaker. So this is two changes together: (1) widen the playable board — larger `Board.radius` and/or a wider-interval axis mapping — so more extreme pitches are reachable, and (2) remove or widen the `Synth.playNote()` clamp to let those pitches actually sound, understanding that very low/high notes won't be audible on hardware that can't reproduce them (that's a real physical limit, not one to also enforce artificially in code). Not yet designed: how far to widen the board (a literal 20Hz–20kHz target is extreme and would make most of the grid inaudible on typical speakers), and whether the same change should apply to Melody mode's target range.

- **Compose: extend/overdub recording**: two related gaps raised after chord entry landed. (1) Resuming a stopped recording currently restarts its clock at 0 (`recordStartTime` resets unconditionally in `startRecording`), so there's no way to "add the next 4 measures" onto an existing take without it overlapping the start. (2) Overdub/layering: re-recording separate takes anchored to the *same* start point, then merging them into one note list, is a real mouse-compatible path to chords (one voice per pass, merged after) since a mouse can never produce simultaneous input the way multitouch can. Needs its own design pass (is layering a UI toggle? does merge just flatten to one list on save, or keep layers distinguishable? how does Undo interact with a layer boundary?) before implementation -- not yet started.
- **#53 Compose mode: link out to an external MIDI editor for rhythm-precision work** (follow-up to #52/task #64): Compose deliberately doesn't build in-app timing-editing (nudge buttons, a timeline) -- a rough recording is cheap to re-record, and real rhythm precision is better served by a dedicated tool working directly on the saved `.mid` file. **Signal** (`github.com/ryohey/signal`, hosted at signal.vercel.app) is a candidate: an in-browser, apparently GPLv3-licensed piano-roll MIDI sequencer, the closest match to "same kind of environment as this app" among the options discussed. Not yet verified firsthand. A true one-click hand-off (opening Signal already loaded with the file) likely isn't achievable anyway -- cross-origin restrictions mean a plain link can't inject a File/Blob into another origin's page, and our saved file isn't at a fetchable public URL (it's a local File System Access folder handle or a downloaded blob) -- so any link would just open Signal and the user re-uploads the file themselves. **Blocked on Gregory personally trying Signal with his own saved `.mid` files first**: confirm the license is actually as understood, and confirm the re-upload workflow is actually palatable, before committing to adding the link.
- **#51 Life mode: hexagonal, Tonnetz-aware cellular automaton** (deprioritized behind Compose mode — see #27 — since the user considers this comparatively exploratory; design work below is already fleshed out and stays valid for whenever its turn comes): a new mode, after Gravity in the mode-slider, where the Tonnetz itself evolves generation-by-generation under a configurable Life-like rule (buttons: Save/Reset/Back/Step/Play-Pause). Starting point is the classic hex rule 6B2/S35 (sillycycle.com/life.html), but the rule *language* goes well beyond plain neighbor-counting from the start: (1) isotropic non-totalistic classes (Paul Callahan's own real notation for hex CAs — for a 6-neighbor ring, counts of 2 or 4 alive split into 3 symmetry classes, named by analogy to benzene substitution: ortho/meta/para; count 3 similarly splits into 3 classes, named here vicinal/asymmetric/symmetric — verified independently via Burnside's lemma over the dihedral group D6, 13 total isotropy classes across all 7 counts), which lets the engine faithfully express Callahan's `6B2a/S2b34` and the Andreen rule `6B2a3a4b/S2a2b4a`; (2) Tonnetz-awareness — counts broken out per musical axis (fifths/major-third/minor-third, exactly `js/tonnetz.js`'s existing p/q/third-axis structure) plus configurable extra neighborhoods beyond the immediate 6 (e.g. "semitone-adjacent" cells, which are 2 hex-steps away, not immediate neighbors, since `Tonnetz.getMidi` isn't injective). Configuration language lives in YAML (vendored MIT-licensed parser, LibreJS-compliant header) specifically so an existing parser can be reused rather than inventing one, documented in a new `docs/life-rules.md`; save files embed their own ruleset so loading a Callahan variant reproduces its exact behavior. Save/load uses its own separate `life/` folder (both local, via File System Access, and a read-only online repo folder — see #27's bundled-songs item for the same mechanism applied to `.mid` files), distinct from Melody/Compose's shared MIDI folder since the file format is entirely different. Not yet started.
